# Post 03: The Execution Gap

**Phase:** 1 — Establish the Problem
**Status:** Draft
**Target:** Week 2, Post 1

---

Every security team I've ever worked with has the same list.

Credentials that should have been rotated months ago. Network segments that should be isolated. OS versions that haven't been touched in years because the app running on them is too fragile. Log agents that never got deployed because it required a change on every host.

Everyone knows what's on the list. Nobody disputes the priority. The work just doesn't move.

This is the part that outsiders misunderstand about enterprise security. They assume the problem is that security teams don't know what needs to be done. They do. The roadmaps are detailed. The risk register is current. The controls are documented.

The problem has never been what to do.

It's been who can safely do it, when, and without breaking something in the process. Every item on that list requires touching infrastructure that someone else owns, operated by a team that is already overloaded, measured on uptime, and understandably risk-averse about changes that didn't originate with them.

So the list grows. The debt compounds. And when something finally breaks, everyone looks at the list and asks why it wasn't addressed.

Because filing a ticket is not the same as executing a change. Having a roadmap is not the same as having a path to implement it.

The gap between knowing and doing is where most security risk actually lives.
