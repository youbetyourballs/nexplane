# SP3 — Demo App (Payments Stack) + Full Smoke Test Design

## Goal
A realistic multi-component demo application (payments-web + payments-api + Redis) installed on an EC2 as systemd services, plus complete smoke test phases exercising the full containerization lifecycle.

## Demo App Components

### payments-api (Python Flask, port 5000)
- Endpoints: GET /health, POST /payments, GET /payments/{id}
- Connects to Redis (localhost:6379) for session state
- Depends on: redis-server

### payments-web (nginx, port 80)
- Reverse proxy to payments-api at localhost:5000
- Serves a minimal HTML dashboard at /
- Depends on: payments-api

### redis-server (port 6379)
- Session/cache store
- Stateful: has /var/lib/redis data directory
- The agent's deepdiscover identifies this as stateful

## Installation
SSM command installs all three as systemd services:
```bash
# Install Python, Flask, Redis, nginx
# Write service files to /etc/systemd/system/
# Start and enable all three services
```

## Kubernetes Manifests (generated by containerize_build)
- payments-api: Deployment + Service (ClusterIP:5000)
- payments-web: Deployment + Service (LoadBalancer:80) + ConfigMap for nginx.conf
- redis: StatefulSet + PersistentVolumeClaim + Service (ClusterIP:6379)

## Full Smoke Test Phases
Phase DEMO-A: Launch EC2, install payments app, verify all services running
Phase DEMO-B: Discover applications, verify all 3 in asset_metadata
Phase DEMO-C: Build images (dry_run=False), push to ECR, verify image_digest
Phase DEMO-D: Deploy to EKS, verify kubernetes_workload assets, health check
Phase DEMO-E: Retire legacy services, verify containerization_status=retired
Phase DEMO-F: Teardown (EKS cluster + ECR repo + EC2)
